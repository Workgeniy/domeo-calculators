# Нормировочная модель: электрика и свет по помещениям

**Источник:** [data/source/lighting-electrical.xlsx](../data/source/lighting-electrical.xlsx) —
таблица, собранная вручную в переписке с DeepSeek.
**Снято:** 2026-08-24.

## Что делает

Из параметров помещения — тип, площадь, техника, пожелания по свету — выводит
**количества**: розетки, выключатели, рамки, метраж трека и ленты, светильники.

**Цен не считает.** Это спецификация, а не смета: она отвечает на вопрос «сколько чего»,
а не «на сколько рублей».

Тем и отличается от портированного [калькулятора розеток с calcal.ru](calc-outlets.md),
который количества не выводит вовсе — их вводит пользователь, — а только умножает
введённое на прайс. Две модели дополняют друг друга, но ценность в этой.

## Входы

На каждое помещение:

| Поле | Тип | Заметки |
|---|---|---|
| Тип помещения | список | 10 значений, ключи `hallway`…`balcony` |
| Площадь, м² | число | |
| Уровень комфорта | Эконом / Стандарт / Премиум | пусто → весь расчёт по помещению нулевой |
| ТВ, компьютеры, торшеры, настольные светильники | числа | |
| Пылесос, стиральная, сушильная, духовка, варочная, вытяжка, ПММ, холодильник, СВЧ | да/нет | по розетке на прибор |
| Учесть мелкую технику | да/нет | +3 розетки запаса |
| Трековое, точечное, подвесное, люстра, бра, лента | да/нет | можно несколько сразу |
| Окон | число | только для ленты; в таблице этого поля не было |

## Справочник помещений

Профиль `domeo` — то, как модель задумывалась. Профиль `excel` повторяет таблицу,
где все помещения считаются по одним и тем же числам (почему — ниже).

| Помещение | м² на розетку | Линий трека | Шаг трека, м | Групп света | Мокрая зона | Проходных |
|---|---:|---:|---:|---:|:---:|---:|
| Прихожая | 6 | 1.5 | 1.0 | 1 | — | 1 |
| Санузел | 3 | 1.0 | 0.8 | 1 | да | 0 |
| Ванная комната | 3 | 1.0 | 0.8 | 1 | да | 0 |
| Гостиная | 5 | 2.0 | 1.0 | 2 | — | 2 |
| Кухня-гостиная | 5 | 2.0 | 1.0 | 3 | — | 2 |
| Кухня | 4 | 1.5 | 0.8 | 2 | — | 0 |
| Спальня | 5 | 1.8 | 1.1 | 2 | — | 2 |
| Детская | 5 | 1.5 | 1.0 | 2 | — | 2 |
| Гардеробная\* | 6 | 1.0 | 1.0 | 1 | — | 0 |
| Лоджия\* | 6 | 1.0 | 1.2 | 1 | — | 0 |

\* Этих двух строк в исходном справочнике не было, хотя в выпадающем списке помещения
есть. Значения проставлены по ближайшему аналогу — **требуют подтверждения**.

Общие коэффициенты — в [data/spec.json](../data/spec.json). Ключевые: комфорт 0.8 / 1.0 / 1.25;
розеток на ТВ-зону 2, на компьютер 3; запас на мелкую технику 3; м² на точечный светильник 1.2
(минимум 2 на помещение); м² на бра 8; ширина окна 2.0 + запас 0.4 на нитку ленты.

## Формулы

Обозначения: `S` — площадь, `k` — коэффициент комфорта, `⌈⌉` — округление вверх.

```text
обычные розетки   = ⌈ S / м²_на_розетку × k + приборы + мелкая_техника + сценарии ⌉
      сценарии    = ТВ×2 + ПК×3 + торшеры×1 + настольные×1
влагозащищённые   = мокрая_зона ? ⌈ (стиральная + сушильная + 1) × k ⌉ : 0
розетки ТВ        = ТВ × 1
розетки интернет  = ПК × 1

одноклавишные     = ⌈ групп_света × k ⌉ + бра + лента
двухклавишные     = (групп_света ≥ 2) + (бра у кровати)
проходные         = из справочника
перекрёстные      = (групп_света ≥ 3)
рамки             = сумма всех механизмов

шинопровод, м     = ⌈ линий_трека × √S ⌉
трековые          = ⌈ шинопровод / шаг_трека ⌉
точечные          = max(2, ⌈ S / 1.2 ⌉)
лента, м          = ⌈ (2.0 + 0.4) × 2 × окон ⌉
люстры            = 1
подвесы           = из справочника (2 на кухне, иначе 1)
бра               = ⌈ S / 8 / 2 ⌉ × 2          (всегда чётное)
```

Коэффициент комфорта умножает только площадную часть розеток и базовые группы света:
розетка холодильника от уровня комфорта не зависит.

## Чем модель отличается от исходной таблицы

Каждое отклонение закрыто тестом в `tests/…/SpecModelTests.cs`.

| Что | В таблице | В модели | Почему |
|---|---|---|---|
| Коэффициенты по типам помещений | у всех одинаковые | из справочника | обращения к листу «Справочник» в таблице не работают |
| Влагозащищённые в ванной | 0 | считаются | условие сравнивает тип со строкой «Ванная», а список даёт «Ванная комната» |
| Розетки ТВ | ТВ×2 + 1 | ТВ×1 | множитель «розеток на ТВ-зону» (это питание) уехал в антенные розетки |
| Розетки интернет | ПК×1 + 1 | ПК×1 | то же самое |
| Перекрёстные | всегда 0 | при трёх группах света | строка-заглушка; по замыслу зависела от числа групп |
| Одноклавишные | база всегда 1 | база = число групп света | следствие того же обрыва справочника |
| Двухклавишные | по списку помещений | при двух группах света | список не включал кухню, хотя групп там две |
| Стиральная машина в мокрой зоне | и в обычных, и во влагозащищённых | только во влагозащищённых | у машины одна вилка |
| Окна под ленту | не спрашиваются, всегда 5 м | входное поле | ширина окна была заглушкой 2.0 м |

Осталось **как в таблице** — это тоже решения, а не недосмотр:

- **Рамок столько же, сколько механизмов.** Сборка в блоки по 2–4 поста дешевле, но
  1 механизм = 1 рамка — явное решение автора таблицы.
- **1.2 м² на точечный светильник.** Единственное число, откалиброванное по реальному
  объекту: изначально было 3.5, после сверки с фактом расчёт занижал втрое.
- **Запас на мелкую технику даёт +3 в любом помещении**, а не только на кухне.
- **Комфорт не трогает розетки приборов** — так в таблице, и так правильнее.

## Почему таблица считает все помещения одинаково

Она начиналась как полноценный расчёт по типам помещений: значения тянулись с листа
«Справочник» функцией `ВПР`. В переписке видно три подхода к починке `#Н/Д` подряд, после
чего ассистент предложил «сделать максимально просто и надёжно» — убрать `ВПР`, ссылки на
«Справочник» и на «Коэффициенты», подставив средние числа прямо в формулы.

Так листы «Справочник» и «Коэффициенты» и остались лежать неподключёнными, а часть
значений на них разошлась с формулами (например, «площадь на один точечный светильник = 3.5»
устарела после калибровки на 1.2).

В коде эта проблема исчезает: подстановка по типу помещения — обычный словарь.

## Эталон

`tests/…/golden/spec.json` — 7 помещений из самого файла (60 м², квартира целиком) и итог
по квартире. **Ожидания взяты из кэша вычислений xlsx**, то есть посчитаны Excel, а не нами.
Профиль `excel` обязан повторять их до штуки — этим и доказывается, что при переносе ничего
не потерялось.

Пересобрать после правки исходной таблицы:

```bash
python tools/golden/generate-spec.py
```

Нужен `openpyxl`. Значения читаются только из кэша: если открыть файл, поменять входы и
сохранить — эталон обновится под новые. Если кэша нет (файл не сохраняли из Excel), скрипт
скажет об этом и не станет придумывать числа сам.

## Что ещё не решено

- **Точность.** Автор таблицы называет 90%, но документированная сверка с фактом одна —
  та самая калибровка точечного света. Чтобы говорить о точности с цифрой, нужны 3–5 объектов
  «вот планировка, вот что реально закупили».
- **Розетка роутера.** В справочнике есть колонка «интернет-розетка по умолчанию» (прихожая,
  гостиная, спальня, детская), но в расчёте она не участвует: интернет-розетки считаются
  только от числа компьютеров. Пока оставлено подсказкой для формы.
- **Гардеробная и лоджия** — коэффициенты наши, не из справочника.
- **Проходные выключатели** берутся по типу помещения. По замыслу это число входов в комнату,
  то есть его лучше спрашивать, когда планировка известна.
